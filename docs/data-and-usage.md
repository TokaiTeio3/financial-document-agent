# 数据与使用说明

## 公开了什么

本仓库只发布实现代码、配置模板、测试、合成样例和人工整理的设计说明。它从原工程按文件白名单导出，再建立新的 Git 历史；不会把私有比赛仓库的旧提交变为公开。

`financial_qa_agent/tests/fixtures/corpus/` 中的五份文件是合成的微型示例。它们用于验证领域检索、页码保留、结构化回答和 HTTP 流程，数值与条款不代表实际公司或真实保险产品。`ground_truth.json` 也是合成的测试标注。

## 没有公开什么

- 官方原始文档、比赛题目、完整标注及参考答案。
- 提交 CSV、API 请求/响应日志、真实证据原文全集。
- 解析结果、索引缓存、虚拟环境、临时文件、API Key。
- 包含比赛材料或个人信息的原始报告文件。

源文档可公开访问，不代表比赛整理后的数据、题库和标注可以再次分发。因此本仓库不附带下载镜像，也不声称取得了第三方数据的再分发授权。真实 badcase 只保留必要的事实转述和少量数值，不附带整页材料。

## 接入自己的数据

1. 仅使用你有权处理的文档；遵守数据提供方的条款和个人信息要求。
2. `run_preprocess.py` 将原始数据转换为保留页码的 Markdown，使用方式见 [运行说明](competition-reproduction.md)。
3. 交互工程设置 `FINQA_DATA_ROOT` 指向标准化后的目录，五个领域使用下列目录名：

```text
<data_root>/
  financial_reports/*.md
  financial_contracts/*.md
  insurance/*.md
  regulatory/*.md
  research/*.md
```

每份 Markdown 可以用 `<!-- page: 1; source: page_0001.md -->` 标识物理页。每个领域目前读取该目录下的 `.md` 文件，不递归扫描任意目录，也不直接解析 PDF。

4. 在 `financial_qa_agent/` 中执行 `python scripts/build_page_index.py`。数据变化后重新构建索引；不要公开生成的索引。
5. 如果有合法题库，可显式运行 `python scripts/evaluate_ground_truth.py --ground-truth <题库路径> --mode agent`。真实模型模式会发送问题与检索片段到配置的模型服务并产生费用。

比赛成绩来自原始提交和报告；复现需要原数据以及可用的模型快照。公开 Demo 不保证复现榜单分数。数据源或模型变更后，新的结果应该单独记录。

## 运行边界

仅建议绑定到 `127.0.0.1` 进行本地实验。当前 FastAPI 应用没有鉴权、配额限制或租户隔离，不应直接暴露到公网。文档内容也可能包含提示注入，领域工具的文档不是可信指令，模型引用需要后续约束。

本项目用于技术展示，不构成投资、保险、法律或合规建议。公开源码本身不改变第三方数据与依赖的许可；本次未替作者选择独立的代码许可证。
