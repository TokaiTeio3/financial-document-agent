# 金融文档问答 Agent

天池 AFAC 2026 赛道四：金融长文本问答挑战参赛项目

面向年报、债券募集说明书、保险条款、监管法规和行业研报五类长文档，构建以证据检索为基础的金融问答 Agent，支持文档定位、跨文档比较、条款核验、金融计算及结构化答案生成。项目采用 BM25 与关键词锚点检索，不依赖 embedding 模型或向量数据库。

## 技术方案

系统将长文档问答组织为“问题约束解析—分层检索—证据整理—动态裁决或计算—答案审计”的流程，重点控制证据的主体、期间、指标、单位和适用条件。

~~~mermaid
flowchart TD
    Q[问题与选项] --> A[原子约束解析]
    A --> D[文档定位：实体、别名、标题与年份]
    D --> R[页面检索：BM25 与关键词锚点]
    R --> E[证据胶囊与覆盖检查]
    E -->|证据不足| B[Query Repair / Bridge 补检索]
    B --> R
    E -->|证据满足要求| J[动态任务路由]
    J --> O[联合裁决或逐选项核验]
    J --> C[受限计算程序执行]
    O --> F[一致性检查与结构化输出]
    C --> F
    F --> T[答案、引用与调用级审计]
~~~

### 1. 异构文档解析与标准化

使用 PyMuPDF4LLM 将 PDF 按物理页转换为 Markdown，并统一处理 TXT 与 HTML。标准化阶段修复中文字符间距、跨行断句和软换行，标记重复页眉页脚，保留表格结构、页码与来源信息。

解析后的文档进入统一目录，检索结果保留 `doc_id`、`page_id` 和源文件路径，便于将答案回溯到原始材料。

### 2. 无向量的多粒度检索

检索分为文档定位、页面评分和页内证据截取三个层次：

- 文档级：结合公司全称、简称、产品名、文件标题和年份，限定候选材料。
- 页面级：以 BM25 为基础，叠加实体、年份、数字、指标名称及低频约束短语的词面匹配。
- 证据级：围绕查询锚点截取局部上下文，针对表格回溯表头与单位，针对连续条款扩展相邻内容。

金融问题中的主体、时间、数值和条款原文具有较强的词面约束。采用词法检索可以直接检查召回依据，减少额外模型与索引服务的部署成本。对大幅语义改写、隐含主体及跨文档关系，词面检索仍存在覆盖不足，需要依靠查询规划和补检索处理。

### 3. 原子约束驱动的 Agent 编排

将问题和选项拆解为主体、期间、指标、单位、数值、条件、例外和量词等可核验约束。根据证据覆盖情况，动态选择联合裁决、逐选项核验或计算路线。

证据不足时，针对缺失约束生成 Query Repair 或 Bridge 查询，而非重复检索全部材料。证据进入模型前整理为带来源的 Evidence Capsule，保留相关原文、检索分数和页面信息。裁决结果包含支持、反驳或未知结论，并关联证据与公开推理摘要。

任务规划、检索、证据压缩、裁决、计算和审计分别承担不同职责。编排依据当前问题及证据状态，不以题号或参考答案决定路径。

### 4. 语义判断与确定性计算分离

金融计算采用“模型生成变量与计算逻辑—受限 Python 执行—结果与证据联合审计”的机制。模型负责识别业务口径及公式，程序负责数值执行，格式化与审计环节核对计算结果和输出契约。

执行器通过 AST 白名单限制可用语法与函数，用于同比增幅、占比、百分点差、单位换算及排序等任务。该机制降低模型心算带来的波动，但不能替代对操作数来源和业务口径的核验，也不等同于完整的安全沙箱。

### 5. 结构化输出与调用级追溯

答案格式由本地程序统一处理，包括选项顺序、数值精度、百分号及空值。调用日志记录请求、响应、检索证据、执行路线、计算结果、异常和原始 Token usage。

EvidenceTable 通过 `call_id`、任务路线、选项、文档、页码及 SHA-256 将模型调用与原文片段关联。结果采用原子写入，支持运行中断后的恢复与逐题复核。

## 技术栈

| 模块 | 技术 |
|---|---|
| 开发与数据结构 | Python、Pydantic、类型化状态、并发执行 |
| 模型调用 | Qwen3.7-Max、DashScope OpenAI-compatible API |
| 文档处理 | PyMuPDF4LLM、Markdown、TXT / HTML 解析、文本标准化 |
| 检索 | BM25、中文字符 n-gram、实体别名、关键词锚点、相邻页扩展 |
| Agent 方法 | Query Planning、原子约束、证据压缩、动态路由、Query Repair / Bridge |
| 计算与审计 | AST 白名单、受限 Python、EvidenceTable、SHA-256、Token 统计 |

## 设计分析与失败复盘

项目中的主要误差并非都来自模型推理。页面召回、证据完整性、操作数共享和业务口径选择需要分别评估。

例如，`fin_b_001` 已召回目标年报页面，但证据窗口在目标表格行之前截断，后续又受到不同收入口径的干扰；`fin_b_003` 中，计算选项缺少已在同题其他调用中出现的营业收入；`res_b_005` 则涉及正文近似值与表格精确值的基准选择，两个公式本身均计算正确。

这些样例说明，仅提高 top-k 或更换模型不足以处理全部问题。改进应分别针对表格完整性、带来源的事实共享、精度与口径冲突开展，并通过回归测试验证。详细记录见 [真实失败分析](docs/bad-cases.md) 与 [设计思路](docs/design-notes.md)。其中已实现的机制和待验证方案均有标注，未开展完整消融的策略不单独归因其分数收益。

## 工程结构与使用

~~~text
src/finqa_agent/          # 检索、推理、计算、运行与审计
src/preprocess/           # PDF / TXT / HTML 解析与标准化
config/                  # 模型、证据预算与运行配置
scripts/                 # 证据构建、验收与辅助工具
tests/                   # 问答与复现流程回归测试
financial_qa_agent/       # LangGraph 封装、领域工具与交互前端
docs/                    # 技术说明、失败分析与复现说明
.github/workflows/       # 离线测试与发布文件检查
~~~

批量问答入口为 `generate_answer.py`，从原始输入依次执行预处理和问答。预处理与索引就绪后的推理也可分别通过 `run_preprocess.py`、`run_reproduce.py` 运行。安装、数据格式及命令参数见 [运行与复现说明](docs/competition-reproduction.md)。

回归测试和发布检查：

~~~powershell
# 仓库根目录：问答与复现模块
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/audit_public_release.py
~~~

公开仓库提供合成样例，不包含比赛原始文档、完整题库与标注、答案 CSV、API 日志、索引缓存或密钥。接入外部文档时需自行确认数据授权，并在本地配置模型凭据。数据准备见 [数据说明](docs/data-and-usage.md)，离线检查结果见 [工程验证记录](docs/release-checks.md)。本项目用于技术研究与工程展示，不构成投资或合规建议。

## 赛后工程整理

赛后使用 LangChain / LangGraph 对任务规划、领域检索和证据汇总进行封装，显式维护 `subquestions`、`subquestion_results`、`evidence`、`token_usage`、`trace` 和 `final_answer`。通过 `Send` 派发子问题 worker，并使用 reducer 合并并行节点的返回结果。Max 负责子问题规划，Flash 负责领域工具调用、证据压缩和最终汇总。

配套 FastAPI 与交互前端，通过 NDJSON 展示节点状态、可折叠的工具输入输出、公开执行摘要、证据引用和分模型 Token 用量。页面索引增加页间双向 overlap 与页内滑动切块，减少分页边缘漏检。计算工具已封装，自动计算节点和题级事实共享仍待完善。
